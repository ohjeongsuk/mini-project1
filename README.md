# 잔고 (Zango)

> 데이터 예측 기반 개인용 스마트 가계부

수입·지출을 **3초 안에** 기록하고, 쌓인 데이터로 **이번 달 지출을 예측**하며,
사용자가 등록하지 않아도 **고정지출을 자동으로 찾아낸다.**

`v1.0.0` · 로컬 개발 완료 (Phase 1~12)

## 빠른 시작

전제: **JDK 21** · **Node.js 22+** · **PostgreSQL 17** · Docker 는 쓰지 않는다.

```bash
# 1) DB 생성 (최초 1회)
createdb miniproject1_db
createdb miniproject1_test

# 2) 백엔드 — http://localhost:8080
cd minipj1-backend
cp .env.example .env        # 값을 채운다 (DB 접속 · JWT_SECRET)
./mvnw spring-boot:run

# 3) 프론트엔드 — http://localhost:3000
cd minipj1-frontend
npm install
npm run dev
```

- Swagger UI: http://localhost:8080/swagger-ui/index.html
- 백엔드가 떠 있어야 데이터 화면이 동작한다. 프론트만 띄우면 화면은 그려지고 API 만 실패한다.

자세한 실행·주의사항은 각 저장소의 `README.md` 와 `CLAUDE.md` 를 본다.

## 핵심 기능

| 기능 | 설명 |
|---|---|
| 거래 기록 | `/transactions` 상단 **퀵 입력 바** 한 줄. 별도 작성 페이지를 두지 않는다 |
| 월 대시보드 | 요약 · 카테고리별 · 일별 추이 · 캘린더 히트맵 · 예산 소진율 |
| **지출 예측** | 직전 3개월 일평균 × 남은 일수로 이번 달 예상 지출을 계산 |
| **이상치 감지** | 카테고리별 지출 *속도*가 기준선 대비 ±30% 이상 벗어나면 알림 |
| **고정지출 자동 감지** | 직전 3개월 + 당월에서 같은 상호·비슷한 금액(중앙값 ±10%)을 찾아낸다 |
| 예산 | 카테고리별 월 예산 upsert, 소진율 표시 |
| CSV | 가져오기 / 내보내기. 엑셀(CP949)이 되돌려준 파일도 읽는다 |
| **챗봇** | 자연어로 금액·내역·예산·예측·고정지출을 물어본다. **조회 전용** |
| 인증 | 이메일 + 비밀번호(BCrypt), 구글 OAuth2 |

## 설계상의 선택

기술 선택의 **이유**는 `CLAUDE.md` 에 있다. 자주 묻는 것만 요약한다.

- **Docker 를 쓰지 않는다.** 로컬 PostgreSQL 을 직접 설치해 쓰고, 테스트도 실제 PostgreSQL(`miniproject1_test`)로 돌린다. 금액 계산이 제품의 본체라 H2 로 바꿔 테스트하면 결과가 갈린다.
- **차트·CSV·폼 라이브러리를 쓰지 않는다.** 차트는 4종뿐이라 자체 SVG/CSS 로 그리고, props 모양만 Recharts 와 맞춰 나중에 갈아끼울 수 있게 뒀다.
- **금액은 전부 `NUMERIC(15,2)` / `BigDecimal`.** 예측·평균·소진율에 나눗셈이 도처에 있어 정수·부동소수점 모두 조용히 틀린다.
- **"오늘"과 "이번 달"을 서버가 판정하지 않는다.** 서버는 UTC, 사용자는 KST 라 매월 1일 0~9시에 지난달 대시보드가 보인다. 클라이언트가 `yearMonth` 와 `asOf` 를 보낸다.
- **반복 거래 스케줄러를 만들지 않는다.** 「고정지출 자동 감지」가 사용자 입장에서 같은 문제를 푼다.
- **챗봇에 LLM 을 쓰지 않는다.** 규칙 기반 파서라 API 키·호출 비용·네트워크 의존이 없고, 동작을 단위 테스트로 고정할 수 있다.
- **챗봇은 조회만 한다.** 자연어는 원래 애매한데, 애매한 입력으로 되돌리기 어려운 일(거래 추가·삭제)을 하게 두지 않는다. 잘못 알아들어도 사용자가 다시 물으면 끝이다.

## 개발 진행

`docs/ROADMAP.md` 의 Phase 단위로 진행했고, 각 Phase 의 완료 조건을 실제로 실행해 확인한 뒤 커밋했다.

| Phase | 내용 |
|---|---|
| 1~2 | 저장소 초기화 · 도메인 & DB |
| 3~6 | 인증 · 거래/카테고리 · 집계/예측 · 예산/CSV (각 Phase 에서 테스트 동반 작성) |
| 7~11 | 프론트 스캐폴딩 · 인증 · 거래 · 대시보드 · 예산/카테고리/CSV 화면 |
| 12 | 전체 검증 → `v1.0.0` |

- 브랜치: `main`(동작 가능 상태) ← `develop` ← `feature/{작업명}`
- 커밋: Conventional Commits, **본문은 한글**
- 태그: Phase 완료 시 `v0.{Phase}.0`, 전체 검증 통과 시 `v1.0.0`
- **API 계약이 바뀌면 이 문서 저장소를 먼저 수정**한 뒤 백엔드 → 프론트엔드 순으로 반영한다
